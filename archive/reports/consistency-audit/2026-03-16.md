## 详细发现

### 发现 1: api-design.md MenuItem 缺失 F11/F12 全部字段 🆕
- **严重度**: 🔴 矛盾
- **涉及文档**: api-design.md §5.1 MenuItemSchema vs shared/types.ts MenuItem
- **具体内容**:
  api-design.md §5.1 的 MenuItemSchema 只包含基础字段（id, nameOriginal, nameTranslated, price, tags 等），**完全缺失** DEC-037/DEC-050 新增的 F11/F12 字段：
  - `brief: string` — 一句话概要
  - `briefDetail?: string` — 展开详情
  - `allergens: AllergenTag[]` — 过敏原标签
  - `dietaryFlags: DietaryFlag[]` — 饮食方式标签
  - `spiceLevel: number` — 辣度 0-5
  - `calories: number | null` — 卡路里估算

  shared/types.ts 和 worker/prompts/menuAnalysis.ts 都已包含这些字段，但 api-design.md 未同步。
- **影响**: 新开发者/Agent 参考 api-design.md 会完全不知道这些字段的存在
- **建议修复**: 在 §5.1 MenuItemSchema 中补齐全部 F11/F12 字段定义

### 发现 2: api-design.md MealPlan 接口严重过时 🆕
- **严重度**: 🔴 矛盾
- **涉及文档**: api-design.md Chat输出格式 vs shared/types.ts MealPlan
- **具体内容**:
  api-design.md 定义的 MealPlan：
  ```typescript
  interface MealPlan {
    courses: { name: string; items: { dishId, name, nameOriginal, price, reason, quantity }[] }[];
    totalEstimate?: number;    // optional
    pairingNote?: string;      // 字段名不同
  }
  ```
  shared/types.ts 定义的 MealPlan：
  ```typescript
  interface MealPlan {
    version: number;           // 缺失
    totalEstimate: number;     // required
    currency: string;          // 缺失
    rationale: string;         // pairingNote → rationale
    courses: MealPlanCourse[];
    diners: number;            // 缺失
  }
  ```
  agentChat.ts Prompt 输出的 JSON 结构与 types.ts 一致，与 api-design.md 不一致。
- **影响**: 文档误导实际 schema，MealPlanCard 前端解析依赖正确 schema
- **建议修复**: api-design.md 中 MealPlan 完整替换为 types.ts 版本

### 发现 3: Analyze 超时值三方矛盾（持续）

- **建议修复**: types.ts 对齐 api-design.md 或反向统一

### 发现 4: EU 过敏原编号对照表错误（持续）
- **严重度**: 🔴 矛盾
- **涉及文档**: worker/prompts/menuAnalysis.ts
- **具体内容**: 编号 2/4 重复映射 shellfish，5/10 重复映射 peanut，与 EU Regulation 1169/2011 不符
- **持续次数**: 第 2 次报告
- **⚠️ 安全风险**: 当菜单使用 EU 标准编号标注过敏原时，映射会出错
- **建议修复**: 修正为 EU 官方编号或标注为非标准参考编号
